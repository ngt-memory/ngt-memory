# NGT Memory — Eval Harness

Измеряет главное свойство памяти: **всплывает ли нужный факт в retrieval**,
когда пользователь задаёт связанный вопрос, не утонув среди отвлекающих записей.

## Запуск

```bash
# Полноценный eval на реальных OpenAI-embeddings
OPENAI_API_KEY=sk-... python -m eval.run_eval

# Без сети — детерминированный псевдо-embedding (проверка пайплайна, НЕ качества)
python -m eval.run_eval --fake-embeddings

# Подбор параметров
python -m eval.run_eval --top-k 3 --threshold 0.2
python -m eval.run_eval --no-graph          # сравнить вклад графа ассоциаций
python -m eval.run_eval --json              # машиночитаемый вывод
```

## Метрики

| Метрика | Что значит | Идеал |
|---|---|---|
| `recall@k` | доля сценариев, где хотя бы один релевантный факт попал в топ-K | 1.0 |
| `precision@k` | доля релевантных среди возвращённых | выше — меньше шума в контексте |
| `MRR` | средний обратный ранг первого релевантного факта | 1.0 = всегда #1 |
| `hit@1` | доля сценариев, где релевантный факт оказался первым | 1.0 |

`recall@k` — самая важная: если нужный факт не всплыл, LLM его не увидит.
`precision@k` и `MRR` показывают, насколько чисто и высоко он ранжирован.

## Режим fake-embeddings

Псевдо-embedding кодирует **лексическое** пересечение (общие слова → близкие
векторы), а не семантику. Поэтому:
- годится для регрессионного теста пайплайна (retrieval, eviction, граф не падают);
- НЕ отражает качество реальных embeddings — синонимы («doctor»/«physician»)
  останутся далёкими, а граф ассоциаций не проявит себя.

Для оценки собственно качества памяти используйте реальный ключ.

## Добавление сценариев

`dataset.jsonl`, по одному JSON на строку:

```json
{
  "id": "краткий-идентификатор",
  "facts": ["релевантные факты пользователя"],
  "distractors": ["нерелевантные записи-шум"],
  "query": "вопрос пользователя, связанный с фактами",
  "expect_keywords": ["слова", "которыми", "опознаётся", "релевантный факт"]
}
```

Эталон считается по ключевым словам: факт релевантен, если содержит любое
из `expect_keywords`. Грубо, но воспроизводимо и без ручной разметки рангов.

## В CI

`--json` даёт машиночитаемый вывод — можно завести порог и падать при
регрессии recall:

```bash
recall=$(python -m eval.run_eval --fake-embeddings --json | python -c "import json,sys; print(json.load(sys.stdin)['recall_at_k'])")
python -c "import sys; sys.exit(0 if $recall >= 0.85 else 1)"
```
